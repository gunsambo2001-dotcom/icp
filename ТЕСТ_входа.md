# Как проверить вход (одна учётка на ученика)

Проверять лучше снизу вверх: сначала логика на реальных данных, потом браузер, потом боевой сервер.
Первые два шага **ничего не меняют** в таблице и не требуют деплоя.

---

## 1. Логика на реальных именах — 2 минуты, без риска

1. Откройте таблицу → **Расширения → Apps Script**.
2. Вставьте новый `apps-script-hub.gs` (Ctrl+A, Ctrl+V), сохраните (Ctrl+S). **Деплой не нужен.**
3. В списке функций сверху выберите **`testNameMatch`** → **Run**.
4. Внизу откройте **«Журнал выполнения»**.

Что увидите: по каждому из первых пяти учеников первого потока — строка `OK` или `FAIL`:

```
Поток ПОТОК-7, учеников в таблице: 12. Проверяем 5.

OK   то же имя            «Иван Иванов» → exact → u1758...
OK   лишние пробелы       «Иван  Иванов» → exact → u1758...
OK   другой регистр       «ИВАН ИВАНОВ» → exact → u1758...
OK   обратный порядок     «Иванов Иван» → exact → u1758...
OK   опечатка (буква)     «Иван Ивано» → similar → u1758... (d=1)

OK   совсем новое имя     «Проверка Тестовая» → none

Всё сходится — вход ведёт себя как задумано.
```

- `exact` — войдёт в существующий профиль (новый не создастся).
- `similar` — покажет предупреждение и кнопку «Это я».
- `none` — создастся новый профиль.
- Если в конце `ЕСТЬ РАСХОЖДЕНИЯ` — пришлите этот лог, разберём.

Функция только читает лист `students`, ничего не записывает.

---

## 2. Стенд в браузере, без Google — 5 минут

Откройте файл `icp/index.html` двойным щелчком и допишите в адресную строку `?api=mock`, то есть:

```
...\icp\index.html?api=mock
```

Внизу справа появится жёлтая плашка «🧪 локальный тест» — значит данные пишутся только в этот браузер, таблица не затрагивается. (Чтобы начать с чистого листа: `?api=mock&reset=1`.)

Сценарий:

| Шаг | Что ввести | Что должно быть |
|---|---|---|
| 1 | поток `ПОТОК-7`, имя `Иван  Иванов` (два пробела) | вход, открылся кабинет |
| 2 | ответить на пару вопросов в любом модуле, нажать «Отправить» | «сделано» в списке модулей |
| 3 | «Выйти», затем войти как `Иван Иванов` (один пробел) | тот же кабинет, ответы на месте, нового ученика нет |
| 4 | «Выйти», войти как `Иван Ивнов` (опечатка) | ⚠️ «Второй аккаунт не создаём» + кнопка «Это я — войти в свой аккаунт» |
| 5 | нажать эту кнопку | вход в прежний кабинет, ответы на месте |
| 6 | «Выйти», войти как `Сергей Кузнецов` | новый кабинет, домашка пустая (это новый человек) |

Проверить, что ученик не задвоился, можно в консоли браузера (F12 → Console):

```js
JSON.parse(localStorage.icp_hw).students
```

Там должно быть столько записей, сколько разных людей вы завели (в сценарии выше — два).

## 3. Боевой сервер после деплоя — 2 минуты

1. **Deploy → Manage deployments → карандаш → Version: New version → Deploy.**
2. Откройте сайт и проверьте как ученик (не как владелец): войдите под **реальным именем реального ученика**, но с одним лишним пробелом или в другом регистре.
   - Должны попасть в его кабинет с его домашкой.
   - Затем выйдите и войдите с опечаткой в имени — должно появиться предупреждение с кнопкой.
3. Если хотите проверить сам сервер без браузера — PowerShell (замените имя на реального ученика):

```powershell
$body = @{ action='login'; stream='ПОТОК-7'; name='Иван  Иванов' } | ConvertTo-Json
Invoke-RestMethod -Method Post -ContentType 'application/json' -Body $body `
  -Uri 'https://script.google.com/macros/s/AKfycbxV5e3F0SB1io48D3RiMauZKxGXg2_MJG02LhQZ82ZgzGk31T8h7F-tNY43r6aFAxZe/exec'
```

Ожидаемый ответ: `ok : True`, `role : student`, `uid : u1758...` — тот же, что у этого ученика в листе `students`.

> ⚠️ Для проверки берите **существующего** ученика. Если ввести имя, которого нет, сервер честно создаст нового ученика — придётся удалить строку из `students`.
> ⚠️ Войдя под учеником, **не нажимайте «Отправить»** в домашке — перезапишете его ответы.

---

## 4. Полный прогон на копии таблицы — по желанию, ~20 минут

Если хочется потрогать всё целиком и совсем не рисковать боевыми данными:

1. В таблице **Файл → Создать копию**.
2. В копии: Расширения → Apps Script → вставить `apps-script-hub.gs` → Deploy → New deployment → Web app (доступ «Все»).
3. Скопировать `icp/index.html` рядом, в копии заменить адрес в `PROD_API` на новый.
4. Пройти сценарий из раздела 2 — но уже на реальном сервере. В копии таблицы будут появляться строки, это нормально.

---

## Важно

- Пока не сделан деплой, боевой сайт работает по **старой** версии скрипта — дубли продолжатся.
- Уже существующие дубли сами не исчезнут: их надо один раз слить (см. «Как один раз почистить старые дубли» в [ИНСТРУКЦИЯ.md](ИНСТРУКЦИЯ.md)).
